## Задачи и процесс (.tasks/, pipeline)

В проекте трекер задач `.tasks/` с процессом pipeline (скилл `task-tracker`, `references/pipeline.md`).
- Нетривиальная работа идёт от задачи. Description — слова пользователя дословно. Каждое следующее его слово по задаче — `note --by user`. Твои выводы на старте и по итогу — `note`.
- Новая функция: сначала груминг. В `Decision` — влияние на основы (`.tasks/tech/pillars.md`), варианты, за и против, выбор. В `todo` задача уходит только по явному «да» пользователя (`--by user`).
- `todo → in_progress` через preflight (решение сверено с кодом). Задачу из todo может взять субагент. Если что-то не сходится, он возвращает вопрос.
- `review` — приёмка пользователем. `qa → done` — только после независимого аудита: новый агент получает бриф `tasks audit brief`, его вердикт записывается `tasks audit add` как есть.
- Хранители (если есть: `guardians` в `.tasks/project.json`, скилл `references/guardians.md`): на груминге каждый говорит своё слово в ТЗ (`tasks guardian brief`/`say`), на Arch QA находку в его зоне — ему на детальное ревью (`tasks guardian review`/`add`).
- Перед работой в области кода: `tasks code` / `tasks code <файл>`. Там известный долг, копии, правила и отметки хранителей.
- Админка: `tasks serve` (задачи, вики, код, страницы проекта), только просмотр. Файлы `.tasks/` руками не правь.
